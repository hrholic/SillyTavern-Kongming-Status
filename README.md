# 统一状态栏

一个独立的 SillyTavern 前端扩展。为**能够明确识别的状态栏**套用统一样式，保留原有内容和交互。当前版本 `0.3.2`，提供原有模板与两种新增的简约模板。

不需要 Extras、酒馆助手或原预设。不联网请求字体、脚本或模型服务，不上传聊天内容。

## 安装

1. 打开酒馆的「扩展」面板，选择「安装扩展」。
2. 填入仓库地址：`https://github.com/hrholic/SillyTavern-Kongming-Status`。
3. 安装完成后刷新酒馆。
4. 在扩展设置中展开「统一状态栏」。

若手动安装，将本仓库放在 `public/scripts/extensions/third-party/SillyTavern-Kongming-Status/`，或酒馆当前用户的 `data/<user-handle>/extensions/` 中。插件根目录必须直接包含 `manifest.json`。

不需要导入原预设，也不需要修改角色卡。请先在一段已有聊天里试用；效果不合适可以关掉插件自身的启用开关，恢复原有显示。

已经安装旧版时，在扩展管理中更新这个扩展，再刷新酒馆即可。**仓库地址、安装目录和旧设置存储键没有改名**，不需要重新安装；原有启用状态、排除名单、额外选择器和日夜偏好都会保留。旧版配置默认沿用原有模板。

## 0.3.2 渲染面板适配试验版

识别对象扩展为正文之外、已经显示出来的独立面板，不限定在正文后，也不要求标签含有 status：

- 通用路径：完整源标签位于正文 / 思考 / 隐藏区之外，页面上有明确面板结构，且多个未改写的可见文字片段唯一对应该源块。允许渲染器新增少量短标题或按钮；不采用整篇模糊相似匹配，也不从原文重建内容。
- 针对已核实的蓝图渲染结构，支持远景、TOP、成就、时间线、摘要和分支。成就表与成就对应两个顺序一致的现有壳；不把源块数量直接当成实际显示数量。
- 以上路径只改外框底色、边线、圆角和阴影，保留内部文字、布局、按钮及折叠行为。隐藏 raw 区不读取、不展示；深入配色不作用于这些外框的内部。
- 明确保护 xp_cot、HTML 注释、原文中的 hidden / aria-hidden / display:none 隐藏区。排除名单仍优先。
- 提供匿名结构替身测试，不包含任何用户聊天原文、原预设脚本或模板代码。

这不是所有角色卡的万能识别器。正则完全重写文字、私有框架、跨域页、无明确面板边界、同名重复模块、未闭合源标签仍可能跳过。蓝图适配依据指定版本的结构，不保证未来模板改版兼容。隐藏或未渲染的模块不会为了凑数量而展示。

## 0.3.1 扩大识别试验版

本版针对已证实的漏识别规则作小范围扩展，不保证覆盖某一张卡的全部面板：

- 没有正文标签时，处理连续的多个末尾状态块，不再只考虑最后一个。
- 标签消失后的独立字段段落可位于嵌套包装容器里，不局限于消息最外层。
- HTML 内缩进不再一律视作代码；显示为 `pre/code` 的内容仍保护。
- 支持 Markdown 表格、括号字段、XML 式字段，允许字段分隔符和列表标记等格式差异。标签和值仍须完整对应且唯一，不能用“内容大概相似”匹配。
- 扩大至消息内其他可见、可读取的 iframe，不限定一种 ID。仍只处理明确状态区或可靠对应的现有容器，不改整个 body，不包装 iframe 里的散乱节点，不处理后台脚本页或跨域页。
- 基础检查 17 项通过；本版没有重跑完整回归、真实酒馆或视觉截图测试。

## 0.3.0 识别与空明样式修正

- 不再仅依赖固定的 `status` 标签：会只读消息原文，寻找已闭合正文之后的完整状态标签，并用字段结构与现有显示内容对应。陌生标签不需要逐个填写。
- 标签被酒馆去掉但内容仍独立显示时，可以对应一个现有容器或连续的顶层段落。仅移动这些现有节点加外框，不从原文生成内容；关闭或排除后恢复。
- 增加同源、可读取的消息 iframe 适配。支持其中明确的状态区，以及具备蓝图 TOP 特征和来源标记的外框。只改外框，保留内部排版、隐藏区和交互。
- 修正空明原先误用的实色圆角卡片：参考原预设最终 CSS 覆盖，改为透明、方角、无阴影、渐隐细线和左对齐书卷排版。预览使用独立编写的章节示例，不代表所有状态栏都具有这些字段。
- 默认保护常见思考 / 推理 / 控制标签；代码、隐藏内容、排除区仍然不处理。

## 保留的 0.2.1 启动修复

- 不再只等 `APP_READY` 事件。打开酒馆后再安装 / 加载扩展，也会独立检查并启动；不要求该事件被重播。
- 酒馆接口或设置容器晚到时会等待重试；等待期间显示提示，禁用扩展会取消所有待启动工作。
- 设置标题显示实际脚本版本 `v0.3.2`，便于确认更新后的代码确实已加载。
- 设置面板重新建立后立即刷新识别状态；核心模块的加载 URL 带版本号，减少升级时混用旧模块缓存的风险。

**识别结果在大开关正下方。** 正常会显示「已启用，当前已美化 N 个状态栏」，或「已启用，当前未识别到可美化的状态栏」。这是当前已加载聊天的计数，不是预览示例的计数。没有匹配结果也不需要先填标签。

若更新后仍看不到自定义设置，请先刷新页面，确认能看到标题中的 `v0.3.2`。如果出现「正在等待酒馆加载完成」或等待失败提示，可点该提示里的「重新加载插件」。这些提示说明加载问题，并不意味着状态栏格式已经检测过。

## 0.2.0 新增

- 设置标题改为 **统一状态栏**。标题收起后也能看到「已启用 / 已关闭」徽标。
- 设置内增加明显的开关与状态文字；「已启用但未识别到状态栏」会明确写出，不再与关闭混淆。
- 增加独立样式预览，使用固定示例，不读取或插入聊天内容。关闭时预览仍可查看，但会标明没有应用到聊天。
- 保留原有模板，新增两种布局与字体处理不同的简约模板。

## 三种模板

- **原有 · 空明**：透明底、方角、无阴影、渐隐细线与左对齐书卷排版；可跟随酒馆或固定日 / 夜。章节预览含小型章节信息、衬线标题、斜体副标题和描边标签；实际消息保留原状态栏结构，不凭空增加章节或字段。
- **墨夜 · 暗色**：固定炭黑底、冷灰文字、细侧线、小圆角与紧凑等宽标题。没有阴影和装饰动画。
- **白纸 · 亮色**：固定纯白底、深灰文字、细顶线、小直角与衬线标题，留白更宽。没有阴影和装饰动画。

墨夜和白纸各自保持暗色 / 亮色，不随酒馆主题变色。切回原有模板时，会恢复原先保存的日夜偏好。模板只改变已识别区域的样式，不重新组织原始状态栏数据。

## 设置

- **启用统一美化**：只处理助手消息。开启 / 关闭会同步更新开关、标题徽标和状态文字；关闭会移除本扩展添加的样式与标记处理。
- **样式模板**：原有 · 空明、墨夜 · 暗色、白纸 · 亮色。切换后立即更新当前聊天和预览。
- **原有模板 · 日夜配色**：跟随酒馆、日间、夜间。新增两种固定模板下此项不可更改，但原偏好不会丢失。
- **深入配色**：默认关闭。开启会覆盖内部常见文字和底色；可能影响角色卡的特殊配色。
- **不识别名单**：填写标签名、类名或 ID，用逗号或换行隔开。例如 `special-status, my-panel`，也接受 `<special-status>`、`.my-panel`、`#my-panel`。
  - 精确匹配名称，不按模糊关键词排除。
  - 自动兼容酒馆给类名加的 `custom-` 前缀。
  - 命中后保留该容器及全部后代的原设计。
  - 为防止父级样式间接改变排除区，也不美化包住它的状态栏外框。
  - 原始自定义标签被剥掉时，仍会利用原文保护对应内容。
  - 改完后失去焦点立即生效，可点击「重新识别」。
- **额外状态栏选择器**：仅用于补充已经渲染为 HTML 容器的特殊卡片。例如 `.custom-my-panel, #custom-card`。只在当前聊天的助手消息内部查找，不会选中酒馆其他界面。排除名单与正文保护仍然优先。

## 自动识别范围

### 默认会尝试

- 名称明确的状态容器，例如 `status`、`status-bar`、`status_panel`、`character_status`、`state_bar`、`stats`，以及带相应 ID / class / data-type / data-role 的块级容器。
- 标有 `data-status` 或 `data-status-bar` 的块级容器。
- 标题明确写着「状态栏」「角色状态」「人物信息」「Status Panel」等的 `details` 折叠栏。
- 带明确状态标题的 `fieldset`、表格，或紧跟状态标题之后的表格。
- 整个段落 / div 已经显示为**独立纯文本**，并完整被已知状态标签包住的片段。例如一段可见的 `<status>心情：平静</status>`：只在显示层隐藏两端标签，内容不变；关闭插件恢复原显示。

- 原文 `content` / `context` 完整闭合之后的其他完整标签：至少三个不同的短「字段：值」，或至少两个字段且其中一个是时间、地点、心情等状态字段；也接受有明确结构的 HTML 表格 / 定义列表。还必须能唯一对应已经显示的内容。没有正文标签时，陌生标签须位于消息末尾的连续状态块中。
- 可读取消息 iframe 中明确命名的状态区；蓝图 TOP 额外要求 `#tb.tb`、标题与元信息结构，以及唯一且位于保护区外的 `top_blueprint` 原文标记。

不会因为普通正文里出现「时间」「心情」「HP」等词，就将其当作状态栏。结构判断仍是保守启发式，不是对内容含义的万能判断。

### 正文和隐藏内容保护

- `content` / `context` 是默认保护标签，不会作为状态栏，也不会美化其内部。常见 `thinking`、`think`、`analysis`、`reasoning`、`preprint`、`ecot`、`cot`、工具调用 / 系统控制标签也默认保护；陌生的控制标签仍不能保证全部识别。
- 只读当前聊天消息的原文，识别原始正文保护区及排除标签。**不修改原文、提示词、聊天元数据或模型上下文。**
- 若酒馆已经剥掉原始标签，仅当候选状态栏的规范化显示文本能匹配到保护区外、且没有在保护区内重复出现时，才继续处理。无法可靠定位就跳过，因此有意允许漏识别。
- 数据中的 `content:` / JSON `"content"` 字段不等同于正文标签；普通 `class="content"` 也不会单独触发正文标签保护。若要排除该类名，可显式加入不识别名单。
- 不展开折叠栏，不取出隐藏内容展示，不复制隐藏源码。带 `hidden`、`aria-hidden`、隐藏样式或位于这些节点内的内容会被跳过。
- `pre` / `code`、表单控件、脚本、SVG、Canvas 不会被作为状态栏处理；一般候选里包含代码、隐藏节点或嵌入页面时也跳过。
- 不修改 iframe 的地址、sandbox 或 srcdoc，不获取跨域权限、不注入原始 HTML，不触碰 Tavern Helper 后台脚本 iframe。消息页面的适配只添加可移除的外框样式。深入配色不作用于 iframe 后代。

### 目前不支持的情况

- **不保证所有标签都能识别。** 酒馆默认会剥掉不少自定义 HTML 标签，类名也可能加上 `custom-`；标签在最终页面中不存在，就不能直接靠 CSS 选择器定位。
- 原始标签消失后，状态与正文混在同一段落，或没有可唯一对应的现有容器 / 连续顶层节点。
- 任意 Markdown / YAML / JSON 代码块，例如 `myst` 状态块；第一版不会把代码块重新解释成面板。
- 跨域 / 不可读取 iframe、后台脚本页，以及没有明确状态区的整页 HTML。不会把整个正文页面当状态栏。
- 未闭合 / 乱序标签、重复文本无法定位、没有足够状态结构的陌生标签。正则增删字段、改写文字或把值转换成纯图片时，仍可能无法对应。
- 只有自由叙述、图片、图标、Canvas 或隐藏数据构成的状态栏；不会为了扩大覆盖而展示隐藏内容。
- 内部固有颜色不会默认强制覆盖，因此 iframe 中复杂卡片的文字 / 内部底色可能仍保留原设计。
- 极强的原有 `!important`、背景图片、Shadow DOM 或其他插件反复重绘时，可能无法完全统一。

日常使用无需填名单或标签：启用后会自动扫描当前已加载助手消息及后续回复；计数在启用开关正下方。排除名单是“不要改”，额外选择器才是手动补充。若某张卡仍没有被识别，可以补一个具体的额外选择器。若原始结构已经被渲染器丢弃，则需要针对那种格式增加专门适配器，不能靠“抓所有标签”的规则安全解决。

## 设计参考与独立实现

原有模板的配色与透明章节式视觉参考「蓝图预设」全局美化的第一个选项 **空明（kongming）**，原预设作者署名 **@KKM**；其 TOP 模块另标注了 **@蛾摩拉、@鸦**。墨夜与白纸为新增的独立简约设计。

- 日间：主文字 `#14161a`，强调色 `#36526a`，透明表面。
- 夜间：主文字 `#eceae6`，强调色 `#a7bfd3`，透明表面。

本仓库代码独立编写，参考最终视觉特征，不包含原预设、原脚本、提示词、授权码或用户聊天。未复刻原预设的主题切换、动画、主脑等实现。原作品有其自己的使用与传播条件，本仓库不授予原作品的任何权利。

不加载外部字体、动画或背景模糊。透明模板的实际对比度随酒馆背景变化；可切换日 / 夜或改用墨夜 / 白纸。它不是原「蓝图」的完整复刻，也不复制其提示词、脚本和专有渲染逻辑。

## 开发与测试

无需构建，酒馆直接加载 `index.js`、`core.js`、`tail.js`、`frames.js`、`panels.js`、`blueprint.js` 和 `style.css`。

```sh
npm install
npm test
npm run test:dom
npm run test:boot
npm run test:tail
npm run test:frames
npm run test:browser
```

浏览器测试默认使用 `/usr/bin/chromium`；其他环境可设置 `CHROMIUM_PATH`。测试页位于 `tests/fixture.html`，可通过本地静态 HTTP 服务打开。

测试覆盖识别边界、排除与嵌套、正文保护、流式更新、编辑 / swipe、开关恢复、原按钮与折叠栏、可见标签处理、隐藏内容保护。具体本次验证情况见 [TESTING.md](TESTING.md)。
